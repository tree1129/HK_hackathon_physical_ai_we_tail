# O6 自然语言视觉 Agent 演示设计

## 目标

把现有控制台的 `Agent` 页面改造成可重复演示的自然语言视觉 Agent 工作区。用户可以通过文字、单轮语音或可选唤醒词指定目标和多步骤任务；页面用 Mock 视觉数据完成目标匹配、计划生成、确认、逐步执行、异常暂停和任务记录。此功能不调用大模型、Agent 后端或机械手动作接口。

## 已确认范围

- 支持文字任务、点击麦克风说话和可选的持续唤醒词。
- 支持多步骤任务，例如“抓住红色杯子，然后放到左侧托盘”。
- 计划执行前必须由用户点击或说出“确认执行”。
- 支持目标歧义追问、目标丢失暂停、取消和急停。
- Mock 演示不向 `/api/action` 或其他控制接口发送 Agent 动作。
- 保留现有控制台导航、全局状态和视觉语言。
- 桌面端与移动端均为正式展示目标。

## 方案选择

采用“紧凑视觉证据 + Agent 优先双栏”方案。桌面端视觉区域约占 38%，Agent 工作区约占 62%。该方案比对话优先页面保留更多机器人现场证据，又比现有视觉优先布局为任务对话和多步骤计划提供更多空间。流程看板方案适合固定讲解，但不利于演示临场自然语言输入，因此不采用。

## 页面结构

### 桌面端

左栏为紧凑视觉证据区：

- 本地 Mock 场景图；
- 红色杯子、蓝色杯子和左侧托盘的检测框；
- 当前锁定目标、候选目标和安全状态；
- Mock 数据标识。

右栏为 Agent 工作区：

- 任务状态、演示模式和唤醒词状态；
- 用户与 Agent 的对话时间线；
- 目标歧义时的候选快捷回答；
- 2 至 5 步的任务计划及当前步骤；
- 确认、修改、取消和重新演示操作；
- 文字输入、麦克风和发送入口。

现有真实物品抓取控件不混入 Agent 演示流程。全局急停仍保留；触发时同时停止前端演示计时器，但 Agent 演示本身不会调用真实硬件动作。

### 移动端

在 `960px` 以下切换为单列，顺序为 Agent 状态与当前对话、当前计划、紧凑视觉证据、输入区。完整计划可展开，当前步骤始终可见。视觉区使用稳定的 `16:9` 比例；候选目标和步骤可换行，不产生横向滚动。输入控件保持至少 44px 触控高度，并为现有底部导航和安全操作区预留空间。

在 `620px` 以下进一步压缩辅助说明和元数据，但不隐藏确认、取消、语音和急停入口。长任务文本允许自然换行，按钮文字不得截断。

## Mock 数据与状态机

新增独立的前端 Agent 演示控制器，包含以下确定性状态：

1. `idle`：等待文字或语音任务。
2. `listening`：麦克风活动或模拟语音播放中。
3. `understanding`：短暂展示任务解析过程。
4. `clarifying`：多个目标匹配时等待用户选择。
5. `planned`：目标已锁定并生成计划，等待确认。
6. `running`：按固定节奏推进计划步骤。
7. `paused`：Mock 目标丢失，等待重新识别或取消。
8. `completed`：任务完成并生成演示记录。
9. `stopped`：急停或取消后终止当前计划。

状态转换只由前端事件驱动，不读取或修改真实抓取状态机。开始新任务、离开页面、取消或急停都会清理未完成的计时器。

Mock 场景包含红色杯子、蓝色杯子、左侧托盘和安全工作区。内置脚本包括：

- 成功任务：“抓住红色杯子，然后放到左侧托盘”；
- 歧义任务：“抓住杯子”，随后回答“红色的”；
- 暂停任务：执行中模拟目标丢失，再选择重新识别；
- 安全任务：文字或语音“停止”立即终止演示。

自然语言解析只覆盖演示词汇和同义表达。无法识别的任务会保留原文并返回可点击示例，不伪装成通用语言模型。

## 语音交互

麦克风采用渐进增强：浏览器支持 `SpeechRecognition` 或 `webkitSpeechRecognition` 时使用真实浏览器转写，语言设置为 `zh-CN`；不支持、拒绝权限或识别失败时，切换到确定性的模拟语音转写。两种路径呈现相同的聆听、转写、理解和确认状态。

唤醒词开关在支持连续识别时监听 `Tail`、`泰尔` 和“小助手”；演示环境始终提供“触发唤醒词演示”的入口，避免现场受浏览器权限或网络影响。计划出现后，“确认”“确认执行”和“开始”触发确认；“停止”“取消”和“急停”优先终止当前演示。

## 文件边界

- `web/index.html`：重构 `page-agent` 的语义结构和可访问标签。
- `web/styles.css`：新增 Agent 双栏、对话、计划、Mock 标注和响应式样式。
- `web/agent_demo.js`：保存 Mock 场景、指令解析、状态机、语音适配和渲染逻辑。
- `web/app.js`：只保留页面导航、全局急停联动和现有运行状态，不再维护旧的 `runAgentDemo` 计时流程。
- `web/assets/agent-demo-scene.png`：本地桌面抓取场景，保证离线演示仍有稳定视觉内容。
- `tests/test_agent_demo_ui.py`：验证页面契约、移动端关键样式、Mock 场景和脚本接入。
- `tests/test_agent_demo.js`：验证解析、歧义、确认门、步骤推进、目标丢失和停止状态。

## 错误与安全表现

- 未识别指令：显示原始输入、说明未形成计划，并提供示例任务。
- 多个候选：不生成可执行计划，先要求选择明确目标。
- 目标丢失：暂停步骤，不自动跳过或假装完成。
- 重复确认：保持单一计时器，不重复执行步骤。
- 语音失败：保留文字输入并切换到模拟语音，不阻断演示。
- 急停：清理计时器并锁定当前计划；新任务必须显式重新开始。
- 所有 Agent 演示操作均不得调用真实 `/api/action`。

## 测试与验收

1. 单元测试先验证状态机在实现前失败，再完成解析、歧义、确认、执行、暂停和停止路径。
2. Python UI 契约测试确认脚本、关键控件、Mock 数据标识和响应式规则存在。
3. 现有 75 个 Python 单元测试继续通过。
4. 桌面端至少验证 `1440x900` 和 `1024x768`；移动端至少验证 `390x844` 和 `430x932`。
5. 浏览器演示完整走通成功、歧义、目标丢失和急停四条路径。
6. 检查页面无横向溢出、文本遮挡、按钮截断和内容重叠。
7. 断开后端运行页面时，Agent Mock 演示仍可完整执行。

## 完成标准

现场演示者可以在桌面或手机上通过文字、真实浏览器语音或模拟语音发起任务，看到 Mock 视觉目标与多步骤计划，经明确确认后播放完整执行过程，并可靠演示追问、暂停和急停。整个过程无需 Agent 后端，且不会产生额外机械手控制请求。
