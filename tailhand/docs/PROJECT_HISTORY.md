# 项目历史与决策记录

## 1. 型号与当前设备

- 对话最初从 “LinkerHand L6 左手版” 开始，随后用户明确纠正为 `O6`。
- 中途曾按右手配置排查，但最终现场确认当前连接的是 `O6 左手`。
- 只读 CAN 探测结果与最终确认一致：右手地址 `0x27` 三次无响应，左手地址 `0x28` 三次返回 `01 fe ff fe fe fe fe`。
- 项目当前默认 `hand_type: left`，网页可在左手 `0x28` 与右手 `0x27` 间安全切换。

## 2. 从基础驱动到视觉控制

早期目标是让 O6 脱离自然语言交互，能直接在终端重复运行。形成了以下能力：

- 张开、握拳、握拳后恢复。
- 单独控制食指、中指等通道。
- 数字一、二、三、四、五，OK 和竖拇指。
- 循环张合与速度/扭矩参数。
- 四指带相位差的连续波浪动作。
- 接近完整握拳行程的大幅波浪动作。

这些成果保存在 `archive/o6-basic-driver/`。当前主线升级为 `apps/o6-camera-teleop/`：

```text
Mac 摄像头
  -> MediaPipe Hand Landmarker / Object Detector
  -> 6 维几何映射或抓取状态机
  -> EMA、死区、位置限幅、20 Hz 发送限制
  -> O6Controller
  -> macOS PCAN 或官方 SDK
```

## 3. 网页控制台设计

网页使用一个进程、一个摄像头线程、一个 O6 控制器。HTTP 线程只把动作放入队列，不直接写 CAN。

两种控制模式互斥：

1. `手势跟随`：显示 21 点骨架和六维映射。切换后仍不发送，必须点击 `启用跟随`。
2. `物品抓取`：检测绿色抓取区中的稳定目标。默认未布防，必须明确点击 `布防识别`。

设备选择与算法模式彼此独立：

- `左手`：CAN ID `0x28`。
- `右手`：CAN ID `0x27`。
- 切换设备会暂停跟随、清除抓取状态、释放旧连接、按新 ID 重连并安全张开。

## 4. 已解决的关键问题

### Mac 能否直接使用

可以。摄像头直接使用 Mac 自带摄像头索引 `0`，不需要 iPhone 连续互通摄像头。

官方 SDK 的 O6 CAN 后端没有实现 Darwin。本项目没有修改官方 SDK，而是在适配层复用 O6 官方 CAN 帧协议，通过 `python-can + MacCAN PCBUSB` 驱动 `PCAN_USBBUS1`。

### 网页能识别但 O6 不动

常见原因按优先级检查：

1. 手势模式尚未点击 `启用跟随`。
2. 页面显示 `dry-run` 或 `dry-run-fallback`。
3. 左右手 CAN ID 选错。
4. 急停锁存，需要重启运行器。
5. O6 供电、CAN-H/CAN-L、终端电阻或 USB-CAN 连接异常。
6. 另一个控制程序正在占用同一摄像头或 CAN 总线。

本次右手配置无动作的直接证据是 `0x27` 无响应，而 `0x28` 稳定响应。切换回左手后，真机后端连接成功。

### 食指和中指无法完全合拢

视觉端需要先记录张开/握拳样本；硬件端点也必须按实际安全行程调整。当前初值：

- 安全张开：`[250, 250, 250, 250, 250, 250]`
- 基础完全握拳参考：`[102, 18, 0, 0, 0, 0]`
- 物品抓取默认采用更保守的 `[110, 35, 55, 55, 55, 55]`

不能因为幅度不足而绕过每次位置变化限制或直接提高未知物品的夹持力度。

## 5. 安全约束

- 所有位置必须正好 6 维并裁剪到 `0..255`。
- 默认 20 Hz、EMA `0.25`、死区 3、每条命令最大变化 12。
- 手短暂丢失时保持最后姿态，超过 500 ms 停止下发。
- 模式切换和设备切换都清空旧状态并安全张开。
- 急停锁存不会被安全张开解除；需重启运行器。
- 物品抓取时，只要人手进入抓取区就禁止闭合。
- O6 没有机械臂，不能主动接近远处物品；物品必须已经位于掌心和抓取区域。

## 6. 未验证或仍需硬件评估的内容

- Windows PCAN/Candle 真机路径未在本次 Mac 环境验证。
- Ubuntu SocketCAN 与 RS485 的说明来自官方 SDK 和源码核对，未在当前设备实机复测。
- 物品抓取没有触觉闭环，不能根据软硬、易碎程度自动控制夹持力。
- 摄像头只能决定手指姿态或触发固定手掌抓取，不能替代机械臂定位。
