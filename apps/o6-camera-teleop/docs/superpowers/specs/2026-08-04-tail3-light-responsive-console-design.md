# O6 TAIL3 浅色响应式控制台设计

## 目标

把 `tail3-control-ui` 的六页面产品结构迁入 O6 摄像头控制台，在同一个网址内提供桌面和移动端布局。手势跟随与物品抓取继续调用现有真实接口，其余能力以明确标注的演示状态完整呈现。

## 约束

- 保持现有 Flask 接口不变：`GET /api/status`、`POST /api/action`、`GET /video_feed`、`GET /depth_feed`。
- 不修改 O6 控制器、安全状态机、视觉识别或命令队列。
- 急停调用真实 `stop` 并遵循后端锁存语义；前端不提供虚假的解除动作。
- 所有页面共用一个 HTML、一个 JavaScript 状态层和一个网址，不维护移动端副本。
- 迁移前基线保存在 `web-backup-before-tail3-light-20260804/`。

## 信息架构

桌面端使用固定左侧导航，移动端使用底部导航。六个页面为：

1. 控制中心
2. 手势控制
3. Agent
4. 设备与校准
5. 任务记录
6. 设置

顶部状态栏持续显示运行模式、后端连接和安全状态。运动页面在移动端额外显示固定安全操作栏，包含当前主操作和急停。

## 页面行为

### 控制中心

使用 `/api/status` 展示真实后端、摄像头、O6 连接、当前模式和安全状态。两个主要入口分别进入手势控制和 Agent/物品抓取。其他设备与最近任务使用演示数据，并标明演示属性。

### 手势控制

页面进入时请求切换到 `hand-follow`。实时画面来自 `/video_feed`，跟随启用、暂停、左右手选择、安全张开和急停分别复用现有 action。六维通道使用真实 `pose` 数据。跟踪状态、识别手别和安全提示由真实 status 驱动。

### Agent 与物品抓取

页面进入时请求切换到 `object-grasp`。摄像头、目标识别、稳定度、布防、解除布防、安全张开和急停连接真实后端。Mac 摄像头与 iPhone LiDAR 来源切换、配对码、RGB/深度双画面、接触面标定和深度清除继续调用现有真实接口。自然语言任务输入、计划预览与步骤时间线属于 Agent 演示层，使用“演示”标识，且不会向硬件发送未支持的动作。

### 设备与校准

O6、Mac 摄像头、iPhone LiDAR、局域网接收器和后端状态来自真实 status。机械臂与尚未实现的外参校准为演示内容。刷新只重新拉取状态，不伪造硬件成功。

### 任务记录与设置

保留参考原型中的完整交互和示例内容，统一显示“演示数据”。设置只保存在当前页面内存，不调用后端。

## 视觉系统

- 页面背景：冷浅灰 `#f4f6f8`。
- 主表面：白色 `#ffffff`；次级表面 `#f8fafb`。
- 正文：近黑 `#182026`；辅助文字 `#66727a`。
- 线框：`#dfe4e8`，卡片圆角 8px，避免悬浮式大圆角卡片和装饰光晕。
- 手势与人工控制：蓝色；Agent 演示：紫色；正常：绿色；警告：琥珀色；危险：红色。
- 摄像头画面保持深色，因为它是媒体内容而不是页面主题。
- 图标优先使用简洁符号或 CSS 图形，不引入新的前端依赖。

## 响应式设计

桌面宽度大于 960px 时，保留左侧导航、顶部栏和内容工作区；手势和 Agent 页面采用主画面加右侧控制区。移动端使用单列，摄像头排在首位，工程诊断折叠到页面后部，页面底部为固定主操作与急停，最底层为六项导航。所有按钮保持至少 44px 触控高度，并为底部安全区域预留滚动空间。

## 状态和错误处理

- 状态接口每 250ms 轮询，与现有控制台一致。
- 请求失败时保留完整页面框架，显示离线状态，不清空演示页面。
- 后端拒绝 action 时显示错误提示，不在本地提前切换成成功状态。
- `emergency_stopped` 为真时，所有运动主操作禁用并显示“需重启运行器解除”。
- 摄像头加载失败时在媒体区域内显示权限与占用提示。

## 验证标准

- 现有 Python 接口测试继续通过。
- 静态 UI 测试验证六个页面、真实 action、演示标识、视频源和移动安全栏存在。
- 浏览器分别以桌面和手机视口验证布局、页面切换、无横向溢出和底部栏不遮挡内容。
- 在运行层中验证左右手、模式切换、跟随启停、视觉来源切换、深度标定/清除、物品布防/解除、安全张开和急停。
- 后端离线时六个页面仍可浏览，真实控制显示离线或禁用状态。

## 回滚

把 `web-backup-before-tail3-light-20260804/` 中的三个文件恢复到 `web/` 即可回到迁移前 UI。项目同时属于 Git 仓库，但备份目录仍作为不影响用户现有未提交改动的直接回滚基线。
